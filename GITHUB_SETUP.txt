ПУБЛИКАЦИЯ КОДА: GitHub -> Zenodo
=================================

Почему именно так: Zenodo сам выпустит DOI при создании релиза, концептуальный
DOI останется стабильным при всех будущих релизах, а у кода появится обычный
адрес, который можно указать в статье рядом с DOI.

ПЕРЕД НАЧАЛОМ
  Репозиторий должен быть ПУБЛИЧНЫМ --- иначе интеграция Zenodo его не увидит.
  В этом каталоге запрещённых файлов нет (проверено: PIDE_database.xlsx и
  photon_fit_table.csv отсутствуют), и .gitignore добавлен как страховка.
  Историю начинаем с нуля: ничего из прежних рабочих каталогов не импортируем,
  иначе удалённый файл останется в истории коммитов навсегда.

1. СОЗДАТЬ РЕПОЗИТОРИЙ
   На github.com -> New repository
     имя:        fp-lqm-code      (или по вкусу)
     видимость:  Public
     НЕ добавлять README, .gitignore и LICENSE --- они уже здесь

2. ЗАЛИТЬ
   cd fp-lqm-code
   git init
   git add .
   git commit -m "Code for the lethal-threshold lesion-repair model"
   git branch -M main
   git remote add origin https://github.com/<ВАШ_ЛОГИН>/fp-lqm-code.git
   git push -u origin main

3. ВКЛЮЧИТЬ ZENODO  <<< ДО создания релиза, иначе релиз не заархивируется
   zenodo.org -> войти через GitHub -> Settings -> GitHub
   (при первом входе GitHub попросит права admin:repo_hook)
   Найти репозиторий в списке и перевести переключатель в ON.
   Если репозитория нет в списке --- кнопка Sync now.

4. СОЗДАТЬ РЕЛИЗ
   На GitHub: Releases -> Create a new release
     tag:   v1.0.0
     title: v1.0.0
     описание: краткая строка о том, что это код к статье
   Publish release.
   Zenodo подхватит архив в течение нескольких минут и выпустит ДВА DOI:
     - concept DOI (версионно-независимый)  <-- ЭТОТ идёт в статью
     - version DOI (конкретно v1.0.0)

5. ДОВЕСТИ МЕТАДАННЫЕ
   Записью управляет .zenodo.json из корня репозитория --- он уже заполнен
   (тип software, автор, ORCID, аффилиация, лицензия MIT, аннотация с оговоркой
   про неперераспространяемые данные). На странице записи проверить и при
   необходимости поправить вручную.

6. ДОБАВИТЬ DOI В РЕПОЗИТОРИЙ
   - бейдж в начало README.md:
     [![DOI](https://zenodo.org/badge/DOI/<CONCEPT_DOI>.svg)](https://doi.org/<CONCEPT_DOI>)
   - в CITATION.cff поле doi: <CONCEPT_DOI>
   Это обычный коммит, новый релиз ради него делать не нужно.

7. ПЕРЕДАТЬ CONCEPT DOI МНЕ
   Подставлю его в 8 мест 6 файлов рукописи и пересоберу как v68.
   Дальше по CHECKLIST.txt из zenodo_metadata.zip: сначала английский
   препринт, потом русский, потом обратная связь hasTranslation.

ЕСЛИ ПОТОМ ПОНАДОБИТСЯ ОБНОВИТЬ КОД
   Новый релиз на GitHub -> Zenodo автоматически добавит новую версию.
   Concept DOI в статье менять не придётся: он всегда ведёт на свежую версию.
